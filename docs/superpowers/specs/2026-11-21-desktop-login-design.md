# Synca 桌面登录与邮箱绑定交互方案

状态：可点击交互稿已完成，供体验；尚未接真实认证或 DirectMail。用户已确定阿里云邮件渠道、桌面 Web/Electron 优先、Apple 登录优先。此文件记录建议的 UI 与账号边界，不把未验收交互当作最终定稿。

## KANO 简评与范围

沿用本轮已讨论的判断：对不愿或不便使用 Apple 登录的用户，替代登录是进入 Synca 的基本型需求 M；对现有满意用户可能为 I。一星反馈是明确证据，但受影响人数、转化改善仍为初步假设。首期增加邮箱验证码和老账号绑定，避免同时加入密码、短信、多种社交登录。先以交互稿验证路径和账号理解，再从真实 ECS 验证主流邮箱送达。交互稿不发送邮件、不建立会话、不读取真实账号；产品代码、已安装 Electron 和现有 Preview 根页面保持不变。

## 当前实现与取舍

- 当前 `LoginView.tsx` 只有官方 Apple JS 按钮，成功后交换 token；失败交换使用 alert，授权失败仅记录控制台。`AuthContext` 继续负责会话及账户切换清理。
- 后端已有独立 user ID，但建用户强依赖 `apple_user_id`；新增邮箱登录必须先解除这项创建限制，并引入独立的已验证登录身份，不能用伪 Apple ID 填充。
- 用户已选择阿里云 DirectMail；本稿只确定体验，尚未核对域名、RAM 权限或发信资格。
- 布局比较：同时露出 Apple 与邮箱表单虽少一次点击，但首屏拥挤且削弱 Apple；推荐 Apple 实心主按钮 + 同宽邮箱描边按钮，点击后进入独立表单。该具体视觉仍待用户体验。
- 第一版桌面落地；原有移动和原生客户端 Apple 登录兼容。邮箱-only 新账号在移动端入口上线前不能声称已经支持原生移动端邮箱登录；上线安排必须对此有明确提示或待多端齐备后开放该注册入口。

## 设计评审结论

1. 类型：输入、账号导航、错误/成功反馈。Apple 第一、邮箱第二。参照 Apple HIG，Apple 按钮不小于其他登录按钮、不需滚动寻找；正式接入使用官方按钮，原型只模拟授权结果。
2. 采用稳定容器。常规桌面左侧轻量品牌/记录示例、右侧登录；640×500 隐去展示区域，仅保留居中的流程。错误文案在表单内显示，不弹系统 alert，不挤动外层窗口。内容超高时内部可滚动，主操作可达。
3. 老用户优先保全：验证邮箱后才能判断是否已有邮箱身份。未绑定邮箱提供“登录原账号并绑定”与“创建新账号”。在验证前不暴露账号是否存在；不按邮件地址相同自动合并。已有绑定账号直接登录。
4. 设置内从“账号与套餐 → 登录方式 → 添加邮箱”进入。绑定到当前账号，原 user ID、记录、分类、购买及套餐归属不变。已有另一账号使用该邮箱时明确提示，首期不做账户合并。

## 可点击路径

- Apple：首页 → 官方授权接力状态 → 模拟成功 → 进入主界面；取消或弹窗未打开时可重试/返回。
- 邮箱：输入邮箱 → 发送中 → 六位验证码 → 验证中；已有绑定身份直接进入；新邮箱先选择关联旧 Apple 账号或创建新账号。
- 老账号绑定：设置入口 → Apple 再次确认身份 → 输入邮箱 → 验证 → 绑定成功 → 登录方式中显示已验证邮箱。
- 邮箱验证码采用单输入框，支持粘贴、数字键盘与 one-time-code 自动填充；明确提交，不在填满最后一位时自动跳转。
- 建议验证码有效期10分钟、60秒重发、5次错误后重新获取；这些是交互稿参数，正式后端需权威计时和跨请求限流。
- 包括格式错误、发信失败、发送过频、验证码错误/过期、绑定冲突。保留邮箱草稿、明确返回；重发提示使用最新邮件中的验证码。
- 首页隐私和条款使用现有站点地址，新窗口打开。不会新造协议或默认同意营销。

## 实现要点与后端边界

- Web/Electron 复用登录流程组件；容器/页面状态与认证请求分离，沿用现有 token 交换和 AuthContext，不重写主界面。
- 账号绑定需要当前账号的近期身份验证和目标邮箱所有权证明；仅靠旧会话或匹配 email 字符串不能完成绑定。
- 未注册邮箱验证成功后返回短期、限用途的证明，只有明确创建/绑定动作才产生副作用。证明绑定邮箱、用途、会话及挑战；一次性消费。
- 单次使用验证码，不记录明文；过期、重发旧码、重复消费和并发绑定由服务端判断。凭证不得进入 Web/Electron 打包资源。
- DirectMail 由 ECS 后端调用，单独最小权限 RAM 凭证和发信子域，记录请求/投递状态，不将 API 接受等同于到达收件箱。上线前完成 Gmail/Outlook/iCloud/QQ/163 的实际投递验收。
- 登录页不反复强制退出已登录用户，不为测试触碰真实账号数据。
- 浅/深色采用现有中性色和紫色强调，按钮46px、输入47px、内容最大350px；错误非仅用颜色表达，保留关联描述和可访问性播报；所有路径可键盘到达。正式版补齐中简/中繁/英文；本稿为简中。

## 验收标准

- Apple 首屏可见、主次明确；邮箱无需打开额外菜单。
- 邮箱/验证码/错误状态外层容器尺寸稳定，640×500无横向溢出。
- 返回保留邮箱，复制粘贴验证码可用，错误恢复不会导致重复创建或绑定。
- 旧 Apple 账号绑定后呈现同一账号；邮箱冲突不自动合并。
- Apple授权取消后可继续操作；Web/Electron授权边界保持现有安全限制。
- 深浅色可读，Tab 顺序合理，长邮箱换行而不挤出按钮。
