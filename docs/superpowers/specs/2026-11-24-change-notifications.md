# Synca 变更通知与增量同步

用户已批准：服务端通知变化，各端增量拉取；Web 和后端本次发布，客户端一起修改但下一包发布。

采用 SSE 而非双向 WebSocket：已有写入 API 保持，通知仅为失效提示。服务端按账号通知，首次连接/重连必须补齐。每五分钟查询小型状态摘要兜底，心跳不带内容；取消十秒业务轮询与三十秒全量。初次加载和缓存恢复仍允许全量。

Web 可见时连接；Electron 主进程维持连接，关闭/隐藏窗口继续角标更新。iOS 前台连接、后台 APNs；原生 Mac 运行时连接。所有推送回调改增量。记录与分类/权益分别比较状态；状态摘要在拉取之前采样，失败或编辑阻塞不确认，防止丢失并发变化。认证和账号切换隔离，服务重启/网络恢复自动补齐，重复通知合并。

客户端离线保存合并后的完整快照，不能把增量覆盖为完整列表。保留手动同步、中文输入、草稿、搜索定位、滚动、分类拖动。静默同步不新增声音或横幅。APNs 需签名能力验证，不把开关打开等同于真实收发成功。

对比方案：仅降频会增加同步延迟；仅 APNs 不覆盖 Web/Windows 且不保证投递。选 SSE + APNs + 五分钟摘要兜底。现有单进程部署不引入 Redis；未来多实例需共享通知总线，摘要用于漏通知恢复。

验收：跨端增删改完成/分类/AI变化；离线恢复/断线/服务重启；重复和并发通知；账号隔离；关闭窗口角标；空闲流量；已有输入与搜索回归。正式 Web 邮箱仍关闭，客户端保留；本次不触发 TF。
