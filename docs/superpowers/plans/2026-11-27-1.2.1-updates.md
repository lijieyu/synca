# 升级 Implementation Plan
Spec: docs/1.2.1-requirements-2026-11-26.md
Goal: 非强制升级提醒，iOS/Mac 跳转商店；Windows 下载完成后重启安装。
Architecture: 服务端显式发布清单只包含已发布版本。Windows 使用 Electron 内置 autoUpdater + Squirrel.Windows 标准安装器，独立 x64/arm64 静态 feed；已有便携包升级路径是先安装带更新器的 1.2.1 安装包。新版便携运行时提供下载安装器迁移，不假装旧 1.2.0 已具备更新能力。
## Global Constraints
- 不推送、不部署、不提交商店，不购买证书。当前清单保持真实已发布1.2.0。
- 仅主进程访问固定 HTTPS 清单/feed；渲染进程不能传任意下载 URL 或执行路径。
- 首次检查延迟，失败不阻塞使用；手动检查显示结果。准备好后用户点重启，草稿已本机保存。
- 安装器迁移校验 SHA256、架构、版本和固定来源，错误保留旧应用；不删除旧便携目录。
## Tasks
1. 版本和清单验证测试；实现发布清单 API 和生成工具。
2. Windows 安装器构建、Squirrel 生命周期、检查/下载/就绪/重启状态及受限 IPC。
3. Web 桌面更新栏与设置手动检查；Mac 商店链接；iOS 原生提示、设置检查、延后提醒。
4. 单测、构建、构建脚本检查；本地提交。Windows 安装/升级实机验收独立标明，不用静态测试冒充。
## 依据
- Electron updates: https://www.electronjs.org/docs/latest/tutorial/updates
- Windows Squirrel updater: https://github.com/electron/electron/blob/main/docs/api/auto-updater.md
- Portable 不支持标准自动更新；NSIS 最新版本要求签名。选已有 Electron 内置 Squirrel 路径，避免自制覆盖运行目录脚本。

## 实现结果与发布步骤
- `/app-updates` 默认只公告已发布 1.2.0；通过 APP_RELEASES_PATH 指向经核验的发布清单。无有效 Windows 安装包时不提示迁移。
- Windows 使用 electron-winstaller 5.4.4，先 `npm run build:windows`，在 Windows 构建机执行 `npm run build:windows:installer -- x64` 和 arm64。输出 Setup.exe、RELEASES、nupkg 和带 SHA256/字节数的 release.json；可通过已有证书环境变量签名，没有自动购买或创建证书。
- 安装器沿用 Synca Electron 的 package/profile，避免用户登录和本机缓存丢失。首次便携迁移不删除原目录；安装版后续由标准 Squirrel 更新器下载并重启更新。
- `prepare-release-catalog.mjs current.json candidate.json` 合并两个架构的已构建清单；核验安装器、首装及 N→N+1 升级后，先上传完整架构目录，再切换 APP_RELEASES_PATH。清单生成工具不会发布。
- 桌面更新 IPC 仅允许受信任主页面，下载地址不能从渲染进程指定。首次安装包须匹配 SHA256 和大小，执行前再次校验；下载失败删除暂存文件。更新安装不能在编辑弹窗或附件上传期间触发。
- iOS/Mac 延迟检查，提醒可延后24小时；关于页可手动检查。商店地址固定，不执行任意返回链接。预览版不连接生产更新服务。
- 5 项桌面策略/状态/完整性测试、发布清单校验测试、原生版本比较测试通过；Web、Electron 界面与 iOS SDK 构建通过。
- Windows 实机安装/升级/失败恢复尚未验证；本机是 macOS，未将静态测试冒充 Windows 运行结果。尚未生成或发布 Windows 安装包，后续发布前必须完成此验收。
