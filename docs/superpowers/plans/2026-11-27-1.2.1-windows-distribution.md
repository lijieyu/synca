## Design and choices
Reuse Electron autoUpdater + existing Squirrel.Windows website installer. Keep portable ZIP alongside installer; first upgrade from 1.2.0 (89) requires launching the new installer, then same-version bridge and subsequent automatic updates. Pin the website profile to its observed legacy path, verified using shipped old runtime/source, never copy live Chromium files between simultaneous processes. Store uses its own profile and MSIX-managed updates. Electron's process.windowsStore and a build channel marker both disable self-updates, independently of renderer claims.
Use existing @electron/packager, add pinned electron-windows-msix (Windows SDK wrapper) for an independent MSIX target. Avoid replacing the whole build system with electron-builder/NSIS: that would replace working Mac packaging and add migration/signing behavior we do not need. Direct website MSIX/AppInstaller would require signing outside the Store; not chosen under no certificate purchase constraint.
Installed Squirrel updates: extend catalog with full nupkg metadata; download from exact official URL, SHA-256/size verify, serve a local ephemeral feed to the existing updater. This preserves mature installation/rollback behavior while failing closed on unverified package bytes. No private signing key or new commercial certificate required.

## Review Focus
- Store must never invoke native Squirrel or website updater, including malformed/missing build marker.
- Old profile identity is proven from shipped 1.2.0, not inferred from package labels; portable app and installer keep login and local drafts across exit/restart.
- SHA-256 package feed cannot redirect, traverse paths, substitute bytes after validation, serve arbitrary files, or survive disposal with leaked handles; new API fields remain backward compatible for Mac/iOS.
- MSIX identity cannot silently fall back to CI identity for release; publisher values escaped, Store version revision=0, ARM64 target correct.
- CI has least privileges and cannot publish to production or leak profiles; screenshot and WACK results reflect actual Windows environment; legal account declarations stay with user.
