# 草稿本 Implementation Plan
Spec: docs/1.2.1-requirements-2026-11-26.md
Goal: 每账号一页 Markdown 与图片，跨端续写，本地优先保存，冲突不丢内容。
Architecture: scratchpads 单行主文档 + scratchpad_conflicts 冲突副本；revision 条件保存。图片复用上传/鉴权/容量管道，messages 标记 scratchpad_asset 并从待办、收藏与 MCP 记录检索隔离；长期保存。仅显式清理未被主文档或冲突副本引用的图片，避免离线编辑时静默删除附件。
## Global Constraints
- 沿用免费100 MB/Pro1 GB；文档保存不消耗新增记录额度。
- 不自动覆盖并发内容；冲突副本可读取、恢复或删除。
- 本地编辑立即持久化；退出账号不混用缓存；网络错误保留 dirty。
- 原生与 Web 用相同 revision、图片 ID 与错误契约。
- 本地提交，不推送；截图最终统一完成。
## Tasks
1. 写 revision、幂等、隔离、冲突副本、图片归属和清理测试；实现表及 API。
2. Web 草稿入口、Markdown 编辑/预览、图片上传、自动保存与冲突恢复；测试同步状态。
3. iOS 同等入口、TextEditor、预览、图片选择、本机保存及冲突处理；编译。
4. 回归 API 与已有收藏/存储测试、Web 和原生构建；本地提交。
## UI 决策
输入/编辑/导航：采用 Notes 的文档入口和单页编辑，工具栏切换编辑/预览；图片按钮与保存状态常驻，避免自动保存提示打断输入。冲突用明确恢复操作，默认保留两份。系统字号、颜色与可访问性标签，三语。验收离线重启、双设备冲突、图片容量、账号切换和长文编辑。

## 实现结果（2026-11-27）
- 服务端独立主文档、revision 条件写入、冲突副本、恢复前保留当前版本；图片复用鉴权、上传预留及总容量，从普通记录查询隔离。
- Web 与原生均有编辑/预览、图片插入、自动保存、本机恢复、冲突选择及副本恢复。原生共享同账号保存状态，避免切换页面产生缓存写入竞争。Web 缓存按服务端 userId 分区，避免邮箱变更或空邮箱串用。
- 图片长期保存；仅显式删除未引用图片，并提示其它离线设备可能仍在使用。引用中的附件服务端拒绝删除。
- 后端相关 86 项测试通过；Web 4 项状态/分类测试通过；原生状态/图片解析测试通过。Web 生产构建和 iOS Local 模拟器 SDK 构建通过，最终增补的冲突期间输入保护也已复验构建通过。
- 原生工程仅新增 18 行源文件引用；撤销 XcodeGen 带来的无关构建设置变化，保留现有签名及沙盒设置。
- 仍待版本最终阶段：浏览器和设备交互验收、离线重启/双设备实际联调、截图；没有发布或部署。
