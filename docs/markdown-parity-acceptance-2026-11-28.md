# Synca 1.2.1 Markdown 统一验收

范围：记录（待办／收藏）与草稿本预览，Web、Windows Electron、iPhone／iPad、原生 Mac。沿用 `dev`，本地提交；没有推送、部署或更新线上客户端。

## 实现与边界

- `web/src/markdown/parse.ts` 是唯一语法入口，基于 CommonMark/GFM；原生用同一份生成代码在 JavaScriptCore 解析，再用 SwiftUI/TextKit 渲染。记录和草稿共用各平台展示组件。
- 同一 `tests/fixtures/markdown-parity.json` 包含 18 组样例：六级／Setext 标题、行内格式、嵌套列表与引用、任务／UTF-16／CRLF、围栏与缩进代码、表格／对齐、链接／引用定义、换行／分隔线、HTML 安全、图片、未完成语法、转义、综合示例、列表空白、嵌套和表格图片。
- 编辑和复制保留原 Markdown；勾选只修改解析器确认的复选框字符，代码中的 `[ ]` 不可操作。记录沿用版本冲突检查与失败回退，草稿沿用本地自动保存和冲突副本机制。
- 只显示当前账号可访问的 `synca-image:UUID` 图片，支持 Markdown 转义／字符实体；外部或无权限图片保留源文本，不自动联网抓取。HTML 不执行，仅支持明确配对、无属性的行内 `<u>`。
- 记录、草稿、冲突副本引用中的图片均受服务端删除保护；保守扫描代码中的字面引用也会阻止删除。该保护须先于新客户端部署。本轮没有执行部署。
- 超过 128 层嵌套退回原文；原生超 32k UTF-16 文档后台解析，超 128 项的复杂／任务列表分组访问，原文不截断。250k／31,250 项压力用例解析约 6.7 秒，并非即时显示；测试期间 UI 心跳仍能执行。
- Web 构建、GitHub parity workflow、Xcode Cloud post-clone 都检查原生 parser bundle；SHA-256 清单绑定源码、锁文件、生成器和输出，避免更新一端遗漏另一端。

## 证据的适用范围

截图来自实际组件运行的隔离验收应用，使用同一份示例文本、合成账号和本地图片。顶部 Record／Scratchpad／Dark／Source 是测试控制，不是产品新增界面。保存成功／冲突由隔离响应验证；不能据此宣称真实跨设备网络同步已验收。

iPhone／iPad 是现有模拟器；Mac 是原生应用；Windows 是实际 ARM64 虚拟机中的隔离 Electron 运行，不是 x64、安装包、Store 签名或生产账号验收。VoiceOver 真人朗读、旧系统和真机未在本轮覆盖。最大辅助字号正文已截图检查；隔离测试头部和草稿工具栏明显占用较多高度，大字体截图不等于整体布局无缺陷。原先完整列表最大辅助字号的工具栏／输入区问题不属于本轮 Markdown 正文修复，不能用隔离正文截图声称已解决。

## 用户后验收

1. 在记录和草稿预览分别看综合样例：标题无井号，嵌套层级、删除线、表格与代码显示一致。
2. 点击任务框，确认状态保存；回到编辑／复制，确认其他字符与换行原样保留。
3. 横向拖动宽表和长代码，纵向滚动仍顺畅；记录展开／收起后位置正常。
4. 查看明暗和大字体截图：正文清晰，图片可见，表格不挤成单字列。
5. 同账号图片可显示，外部图片／代码中的图片语法保持原文；删除仍被记录使用的图片被拒绝。
